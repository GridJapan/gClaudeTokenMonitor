Claude Code の消費を、
常時計測する。

    

      gClaudeTokenMonitor (ctm) は、Claude Code のセッションログを差分読みして
      トークン消費量とコストを 1 秒ごとに更新表示するターミナルモニター。
      Go 標準ライブラリのみ・外部依存ゼロ・単一 exe。
      タスクバー常駐 UI と、5 分ごとの公式プラン使用率の記録つき。
    

    

      v0.1.1
      Windows 10/11
      Go / 依存ゼロ
      MIT License
    

    

      ↓ zip をダウンロード
      GitHub でソースを見る
    

    

      
    

    
このページのスクリーンショットの数値は、デモ用に合成した計測データです。

  






  

    
WHAT IS THIS

    
ログを読むだけ。API キーも設定も不要。

    

      Claude Code は全セッションの応答を ~/.claude/projects/**/*.jsonl に書き残している。
      ctm はそのログを tail（差分読み）して、assistant メッセージの usage を集計する。
      計測対象のセッションには一切触れないので、観測者効果が起きない。
    

    

      同一メッセージが複数行書かれる Claude Code のログ仕様（実測 1.7 倍の水増し）は
      message.id + requestId をキーに重複排除。キャッシュ書き込み 5 分 / 1 時間 /
      読み出しを分けて、それぞれ正しい料金レート（1.25x / 2.0x / 0.1x）で換算する。
    

  






  

    
DEMO 01 — LIVE

    
いま燃えているか、あと何分もつか。

    

      

        

          レートリミットの実体である 5 時間ブロックを自動検出し、
          進行バー・バーンレート（tok/min）・ブロック終了時点の着地見込みを表示する。
          直近 60 分はスパークラインで、どの瞬間に燃えたかが分かる。
        

        

          更新は 1 秒ごと。1〜6 でビュー切替、r で再スキャン、
          q で終了。
        

      

      

    

  






  

    
DEMO 02 — TASKBAR

    
水槽が満ちたら、休憩の合図。

    

      CtmMonitor はタスクバーに常駐する小さな窓。5 時間制限（手前・青）と週間制限（奥・紫）を
      2 層の水槽として描き、消費が発生するたびに +N フロートが発生源のプロジェクト名を添えて浮かぶ。
      ドラッグすると水面が揺れる物理演出つき。
    

    

      

      

      

    

    
クリックで表示単位（Auto / K / M / RAW）とレイアウトを切替。右クリック →「Windows 起動時に開始」で常駐化。

  






  

    
DEMO 03 — VIEWS

    
6 つの切り口。キー 1 つで切替。

    

      日別・モデル別・プロジェクト別・セッション別・5h ブロック別。
      「昨日いくら使ったか」「どのプロジェクトが食っているか」「いま動いているセッションはどれか」が
      即答できる。
    

    

      
      
      
      
    

  






  

    
DEMO 04 — ALWAYS-ON

    
「測ろうと思ってから準備する」のを、やめた。

    

      

      

        

          常駐レコーダー ctm record が全セッションを ~/.ctm/ に
          アーカイブし続ける。Claude Code を何個立ち上げても、途中で新しいセッションを開いても、
          設定なしで記録される。
        

        

          計測はあとから期間を切り出すだけ:
        

        

          
●●● ctm query 

          
$ ctm query -from "13:00" -session 1a2b3c4d

        

        

          再起動してもバイトオフセットから再開（取りこぼし・二重記録なし）。
          UI の「過去ログ」からは日別明細と指示（プロンプト）ごとの内訳も追える。
        

      

    

  






  

    
DEMO 05 — PLAN LIMITS

    
公式の使用率と、実測の消費を同じ行に。

    

      Claude Code が画面に出す「5 時間制限 / 週間制限」の公式な使用率（%）を
      Anthropic の API から取得し、同じ時間窓で ctm が実測した消費と並べて記録する。
      「何 % のとき、いくら分を消費していたか」が残るので、窓の容量を逆算できる。
    

    

      
●●● ctm limits

      
$ ctm limits

プラン使用制限  max / default_claude_max_20x

  5時間制限
   使用率    0.0% ............................
   リセット  4h55m後 (08-22 20:09)
   実測消費  7 メッセージ / 3.28M トークン / $2.074

* 週間・全モデル
   使用率    8.0% ##..........................
   リセット  106h45m後 (08-27 01:59)
   実測消費  1,036 メッセージ / 275.44M トークン / $231.58
   窓の容量  3.44G トークン / $2895 相当（この使用率からの逆算）
   残り      $2663 相当

    

    

      常駐レコーダーが既定で 5 分ごとにサンプリング。複数マシン運用では
      「% はアカウント全体・実測はそのマシンの分だけ」という非対称を利用して、
      他マシンの消費も推定できる。
    

  






  

    
FEATURES

    
機能一覧

    
    
      
  • 重複排除 — message.id + requestId で水増しを除去（これをやらないと約 2 倍の過大計上）
    • 
      
  • 差分読み — バイトオフセット保持。書きかけ行は次回へ持ち越し
    • 
      
  • キャッシュ内訳 — 5m / 1h 書き込みと読み出しを別レートで課金換算
    • 
      
  • 5h ブロック検出 — レートリミット窓の自動区切りと履歴
    • 
      
  • バーンレートと着地予測 — 直近 5 分から線形外挿
    • 
      
  • -session new — これから始める別セッションだけを計測
    • 
      
  • -since-now — 「今から先」だけを計測
    • 
      
  • ctm query — アーカイブから期間切り出し・実稼働クラスタ検出
    • 
      
  • 公式使用率の記録 — 5h / 週間の % と実測を同じ行に
    • 
      
  • JSON 出力 — 純 ASCII でスクリプト連携（PowerShell / jq）
    • 
      
  • クラッシュ自動復旧 — UI がレコーダーを監視し証跡を残して再起動
    • 
      
  • 二重起動拒否 — ハートビート付きロックで多重記録を防止
    • 
      
  • ATOMS3R サブモニタ — 机上の USB 小型ディスプレイ（v0.2 で提供予定）
    • 
    

  






  

    
VS

    
既存の見方との違い

    

      

        
          
Claude Code の /cost 等都度実行の集計 CLIctm

        
        
          
リアルタイム表示セッション内のみ✕（実行した瞬間だけ）◯ 1 秒更新・全セッション横断

          
常時記録✕✕◯ 常駐レコーダー（追記専用）

          
測り始めの準備不要その都度実行不要（常に記録済み。あとから切り出す）

          
公式使用率（%）との突合% 表示のみ✕◯ % と実測消費を同じ行に記録

          
キャッシュ種別ごとの料金レート—ツールによる◯ 5m/1h/read を分離（費用が 20 倍違う）

          
導入—ランタイムが要る場合ありzip 展開のみ・依存ゼロ

        
      

    

    
表示コストはリスト価格ベースの推定値。定額プラン（Pro / Max）では実請求は発生しない。

  






  

    
INSTALL

    
インストール（zip 展開だけ）

    

      前提は 2 つ: その PC で Claude Code を使っていること。
      プラン使用率（%）も見たい場合は claude にログイン済みであること。
      Go / .NET / Python のインストールは不要。
    

    
    
      
  1. Releases から ctm-*-windows-amd64.zip をダウンロード
    2. 
      
  2. 任意のフォルダ（例 C:\tools\ctm）に「すべて展開」（フォルダ構成は変えない）
    3. 
      
  3. 直下の CtmMonitor.exe をダブルクリック → レコーダー（bin\ctm.exe）も自動で起動
    4. 
      
  4. 常用するなら右クリック →「Windows 起動時に開始」
    5. 
    

    
ctm-0.1.1-windows-amd64.zip
├── CtmMonitor.exe   ← これをダブルクリック
├── bin\ctm.exe      CLI / レコーダー（自動起動される）
├── README.md / INSTALL.txt / LICENSE

    

      
●●● 動作確認 

      
$ .\bin\ctm.exe status
レコーダー: 稼働中
  記録先       C:\Users\you\.ctm
  本日の記録   588 メッセージ / 100.77M トークン / $242.97

    

    

      SmartScreen に止められたら: exe を右クリック → プロパティ →「許可する」→ OK。

      Smart App Control が有効な PC では、ダウンロードした未署名 exe は解除不能でブロックされる
      （v0.1.1 からはブロックされたことがバルーンと crash.log で分かる）。その場合は下のソースビルドで。
    

    
ソースからビルドする場合

    

      
●●● build from source 

      
$ winget install Git.Git GoLang.Go
$ git clone https://github.com/GridJapan/gClaudeTokenMonitor.git
$ cd gClaudeTokenMonitor
$ .\build.ps1
$ .\bin\CtmMonitor.exe

    

    
必要なのは Go 1.22+ と Git だけ。CtmMonitor は Windows 標準の csc.exe でビルドされる。
