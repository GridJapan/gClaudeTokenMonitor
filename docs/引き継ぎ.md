## 2. 経緯：なぜこの設計なのか

### 計測対象に触れない

当初は「計測手順を対象セッションの指示書に書き込み、対象自身に計測させる」方式を検討していたが、
これは成立しないと判断した。理由は 3 つ。

1. **搭載コスト** — 計測手順がコンテキストに常駐し、全メッセージの cache-read に上乗せされる
2. **実行コスト** — 計測作業（スクリプト作成・実行・結果記入）自体が計測値に混入する。
   しかもセッション終盤＝コンテキスト最大の時間帯なので単価が高い
3. **原理的な不完全性** — 集計を実行した後のメッセージは、その集計値に構造的に含まれない（不動点問題）

加えて利害相反がある。実際、対象に計測させる方式のスクリプトには 1.7 倍の過大計上バグがあったが、
**外部から独立に測ったから発覚した**。自己計測では検出できない。

そのため ctm は `~/.claude/projects/` を**外から読むだけ**で、対象セッションに何も要求しない。
この一方通行は設計の核なので、崩さないこと。

### 常時記録にした理由

「測ろうと思ってから準備する」方式では、準備の前に始まった作業を測れない。
`ctm record` を常駐させて全部記録し、**あとから期間を切り出す**（`ctm query`）ようにした。
セッションを何個立ち上げても自動で対象に入る。

## 3. 落とし穴（踏んだもの）

### 重複排除は必須

Claude Code のログは 1 つの応答を `requestId` 単位で**複数行**書く。素朴に数えると膨らむ。

| | 素朴な集計 | 正しい値 |
|---|---:|---:|
| メッセージ | 397 | **232** |
| トークン | 137,930,444 | **81,365,896** |

キーは `message.id + "|" + requestId`。`parser.go` が生成し、`store.go` / `record.go` が使う。
**新しい集計経路を足すときは必ずこのキーを通すこと。**

### キャッシュ失効で 1 通 $6 かかる

中断して 1h キャッシュが切れると、再開時にコンテキスト全量を書き直す。実測値:

| 中断 | cache-write | コスト |
|---|---:|---:|
| 78 分 | 649,023 | **$6.51** |
| 8 時間 | 632,193 | **$6.38** |

ある 12 時間の計測では、これが 3 回で $15.65、**総額の 25.2%** を占めた。
`ctm query` は `cache_read == 0 かつ cache_write >= 50,000` を「キャッシュ失効による再構築」として
自動検出・分離表示する（`query.go` の `resumeCW`）。

### 経過時間と実稼働時間は別物

同じ計測で経過 541.9 分 / 実稼働 27.3 分ということが起きる。$/min が 20 倍変わるので必ず区別する。
`query.go` の `splitClusters` が 10 分以上の空白で区切る。

### JSON は純 ASCII で出す

日本語のプロジェクト名が入ると、CP932 の Windows コンソール経由で `ConvertFrom-Json` が失敗する。
`main.go` の `asciiEscape` が非 ASCII を `\uXXXX` にする。**この処理を外さないこと。**

### ファイルは共有で開く

レコーダーがログを掴んだままなので、読む側は `FileShare.ReadWrite | Delete` が必要。
C# 側で `File.ReadLines` を使うと `IOException` になる（一度踏んだ）。`Store.ReadLines` を使うこと。

## 4. プラン使用率の取得

画面の「5時間制限 / 週間・全モデル / 週次・Fable」の％は**ローカルのどこにも保存されていない**。
Claude Code が描画のたびにサーバへ問い合わせている。

同じエンドポイントを、Claude Code が保存済みの OAuth トークンで叩ける。

```
GET https://api.anthropic.com/api/oauth/usage
  Authorization: Bearer <accessToken>     ~/.claude/.credentials.json の claudeAiOauth
  anthropic-beta: oauth-2025-04-20        必須
```

- トークンに `user:profile` スコープが必要
- **Anthropic 側がレート制限する**。既定 5 分間隔・429 で指数バックオフ。短くしないこと
- 出典: [steipete/CodexBar](https://github.com/steipete/CodexBar) の `docs/claude.md`「OAuth API」節

`limits` 配列の `kind` が `session` / `weekly_all` / `weekly_scoped` で UI の 3 行に対応する。

## 5b. 対応済み（2026-08-22）

| 項目 | 対応 |
|---|---|
| 更新粒度が噛み合っていない | 取り込み既定 **200ms**・UI ポーリング **200ms** まで短縮（実測: 生ログ追記→アーカイブ反映 平均 188ms、定常 CPU 1.7%/コア）。変化が無い tick はディスクに一切書かず、ハートビートは 2 秒に 1 回。UI は増分読み（バイトオフセット保持）で全量パースを回避 |
| `seen` マップが無制限に増える | キーに日付を持たせ、2 万件を超えたら 2 日より古いものを落とす（`pruneSeen`）。剪定は 1 日 1 回 |
| SIGTERM 非対応 | `signal.Notify` に `syscall.SIGTERM` を追加。Unix の `systemd stop` でもロックを解放して終わる |
| 単位切替が永続化されない | `~/.ctm/ui.json` に保存。単位・**ウィンドウ位置**・**レイアウト**を記憶する |

あわせて、起動時に残留した `record.stop` を削除するガードを追加した。
これが残っていると新しいレコーダーが最初の tick で自死する。

## 5c. コンパクト窓の操作（2026-08-22 変更）

| 操作 | 動作 |
|---|---|
| 左クリック | **レイアウト切替**（Detail ⇔ Big） |
| ドラッグ | 移動（位置を記憶） |
| 右クリック → 表示単位 | AUTO / K / M / RAW を**チェック式**で選択 |
| 右クリック → 過去ログ | 詳細窓 |

レイアウトは 2 種類。

- **Detail**: 各制限枠のバー・トークン・コスト＋今日の合計
- **Big**: 今日のトークン数を中央に大きく表示（36pt・幅に応じて自動縮小）。**背景は水槽**
  （水位 = 5 時間制限の使用率、二層の正弦波が常時揺れる）。**ウィンドウをドラッグすると物理で水が揺れる**。
  揺れは実物の水槽と同じ固有モードの重ね合わせで表現している（FxTick 内）:
  m1 基本モード cos(πx/W) は水平加速度で励起され片側に曲面で寄る、m2 対称モード cos(2πx/W) は
  縦加速度で励起され中央がぼよんと跳ねる（Faraday 波の近似）、m3 高次モードは細かい返し波。
  高いモードほど固有振動数が高く減衰が速い。強い縦ジャークでは水面からしぶき（type=1 粒子）が
  飛び、重力で放物線を描いて着水すると消えて小さく波を立てる。bob は水位全体の慣性、chop は
  撹拌量。1 フレームの移動量は ±40px にクランプ、粒子は 140 個で頭打ち。増分が来るとスプリング補間でカウントアップし、増分の大きさで
  4 段階の演出が乗る: スケールパンチ / シマー / 数字の縁のリングから外向きに弾ける
  十字型のキラ星（グロー・強いまたたき・白青金の 3 色）/ 1UP 風の +N フロート
  （13pt、ease-out で 58px すーっと昇る）、tier4 はシェイク。
  数字の色は状態で変わる: 平常 = 白、使用率 70%+ = 橙、90%+ = 赤、
  カウントアップ中 = ミント緑、バースト直後 = 金色フラッシュ。
  30fps の演出タイマーは Big 表示中かつ非最小化のときだけ回る。
  ログ形式は `docs/ログ形式.md` — 別プロセスがトークン消費を読むときの正典

Big の数字は窓幅に収まるようフォントサイズを自動縮小する。単位（K/M/RAW）の指定がそのまま効くので、
「M で大きく」といった見せ方ができる。

## 6. コードレビューの記録

grok（xAI CLI）で 1 回レビュー済み。指摘のうち以下は**対応済み**。

- ロックの TOCTOU → `O_CREATE|O_EXCL` でハンドル保持に変更
- offset の確定が flush 成功より前 → スナップショット＋ロールバックに変更
- heartbeat が tick 末尾だけ → 長処理の前後にも打つ
- `claude --version` に timeout 無し → 3 秒 timeout ＋ `sync.Once`
- `weekly_scoped` のモデル照合 → 表示名を正規化して ID と比較（`normalizeModelName`）
- ゼロ除算 / `-interval 0` の panic / error の握り潰し → 修正
- status と lock の stale 閾値の不一致 → lock に interval を持たせて一本化

セキュリティ（OAuth トークンの漏洩）は「なし」と判定された。トークンは `Authorization` ヘッダにのみ載り、
ログには出していない。**この性質を壊さないこと。**
