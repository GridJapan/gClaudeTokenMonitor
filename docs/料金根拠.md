> "The $2/$10 per million input/output token pricing for Claude Sonnet 5, announced at
> launch as introductory pricing through August 31, 2026, is **now the standard price**.

## プロンプトキャッシュの倍率

ソース #1「Prompt caching」節の表より（#3 と整合）。ctm では `pricing.go` の `Cost()` が
input 単価にこの倍率を掛ける。

| 種別 | 倍率（対 input 単価） | #1 の原文 |
|---|---|---|
| cache-write 5m | **1.25x** | "5-minute cache write — 1.25x base input price" |
| cache-write 1h | **2x** | "1-hour cache write — 2x base input price" |
| cache-read | **0.1x** | "Cache read (hit) — 0.1x base input price" |

倍率でなく絶対額でも #1 の表（5m Cache Writes / 1h Cache Writes / Cache Hits 列）と
全モデルで一致することを確認した（例: Opus 5 = $6.25 / $10 / $0.50）。

## Fast mode

ソース #1「Fast mode pricing」節・#5 より。`usage.speed == "fast"` の行に適用。

| モデル | input | output |
|---|---:|---:|
| Claude Opus 5 / Claude Opus 4.8（fast） | $10 | $50 |

ctm の `claude-opus-5-fast` / `claude-opus-4-8-fast` と一致。
"Prompt caching multipliers apply on top of fast mode pricing"（#1）のとおり、
fast 時もキャッシュ倍率は fast の input 単価に対して掛ける。

## thinking トークンの扱い

`thinking_tokens` は `output_tokens` の内数であり（アーカイブにも内数として記録）、
**別課金は存在しない**。output 単価で課金済みのため、コスト計算では加算しない。

## ctm が採用していない課金要素（既知の非対応）

以下は実際の API 課金には影響するが、セッションログの `usage` から判別できない・
または定額プラン利用では実請求が無いため、ctm のコスト推定には含めていない。

| 要素 | 公式の扱い（#1） |
|---|---|
| Batch API 割引（50%） | 対象外（Claude Code は Batch を使わない） |
| `inference_geo: "us"` の 1.1x | usage に `inference_geo` はあるが倍率は未適用 |
| Web search（$10 / 1,000 回） | トークン外課金のため対象外 |
| ツール定義のシステムプロンプト加算 | input トークンに含まれて記録されるので追加処理不要 |

## 免責

ctm の `cost_usd` は**公開リスト価格による換算値**である。定額プラン（Pro / Max）では
実請求は発生しない。従量課金アカウントでも、割引・クレジット・上記非対応要素により
実請求と一致するとは限らない。「もし API 従量課金だったらいくら相当か」の目安として読むこと。
